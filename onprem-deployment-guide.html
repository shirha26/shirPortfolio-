On-Prem Deployment Guide

Step-by-step instructions for installing and upgrading images on an on-premise environment. Fill in the configuration below — all commands update automatically.

⬡ No environment configured
⚙ Deployment Configuration Live
1
Connect & Switch to Root

SSH into the master node and switch to root before running any commands.

bash
sudo su -
2
Create Upgrade Directory

Navigate to the upgrades folder and create a new directory for this deployment. Copy the scripts from the previous version.

bash
cd /data/rke2-artifacts/docker_images/multiple-archives/upgrades/ mkdir <VERSION> cp <PREV_VERSION>/save-docker-images.sh <VERSION>/ cp <PREV_VERSION>/upload-docker-images.sh <VERSION>/ cd <VERSION>/
3
Create docker-images.txt

Create the image list file with the three image tags for this deployment.

bash
cat > docker-images.txt << 'EOF' 302631773488.dkr.ecr.us-east-2.amazonaws.com/webapp:<PLATFORM_TAG> 302631773488.dkr.ecr.us-east-2.amazonaws.com/deployment_manager_ui:<IMPALA_UI_TAG> 302631773488.dkr.ecr.us-east-2.amazonaws.com/impala_api:<IMPALA_API_TAG> EOF
ℹ Verify the file with: cat docker-images.txt
4
Pull & Save Images from ECR

Authenticate with AWS SSO and pull all images locally. If you need to set up a profile on the machine first, follow the AWS CLI & SSO setup guide.

bash
export AWS_PROFILE=aws aws sso login --profile $AWS_PROFILE
⚠ After SSO login, always restore the local kubectl context — otherwise commands will point to the wrong cluster: kubectl config use-context default
bash
kubectl config use-context default
bash
bash save-docker-images.sh

Expected output — all three images should show pull success:

expected output
Image pull success: 302631773488.dkr.ecr.us-east-2.amazonaws.com/webapp:<PLATFORM_TAG> Image pull success: 302631773488.dkr.ecr.us-east-2.amazonaws.com/deployment_manager_ui:<IMPALA_UI_TAG> Image pull success: 302631773488.dkr.ecr.us-east-2.amazonaws.com/impala_api:<IMPALA_API_TAG>
5
Upload to Local Registry

Push all images to the on-prem Docker registry.

bash
bash upload-docker-images.sh

Verify the images are in the registry:

bash
curl -k https://docker-registry.onprem.local/v2/302631773488.dkr.ecr.us-east-2.amazonaws.com%2Fimpala_api/tags/list curl -k https://docker-registry.onprem.local/v2/302631773488.dkr.ecr.us-east-2.amazonaws.com%2Fwebapp/tags/list
✓ Confirm the new tags appear in the response before proceeding.
6
Update main.yaml Files

Edit each role's vars file and update the image_tag1 value. In vi: press i to edit, then Esc → :wq → Enter to save.

Platform (webapp)
bash
vi /data/rke2-artifacts/ansible/onprem_deployment/roles/platform/vars/main.yaml
set image_tag1 to
image_tag1: "<PLATFORM_TAG>"
Impala UI
bash
vi /data/rke2-artifacts/ansible/onprem_deployment/roles/impala-ui/vars/main.yaml
set image_tag1 to
image_tag1: "<IMPALA_UI_TAG>"
Impala API
bash
vi /data/rke2-artifacts/ansible/onprem_deployment/roles/impala-api/vars/main.yaml
set image_tag1 to
image_tag1: "<IMPALA_API_TAG>"
7
Run the Upgrade

Run each command separately and wait for status: finished before running the next one.

bash — navigate to ansible
cd /data/rke2-artifacts/ansible/onprem_deployment/
bash — upgrade impala-api
python upgrade_applications.py --deployment_name impala-api --redeploy_only True
bash — upgrade impala-ui
python upgrade_applications.py --deployment_name impala-ui --redeploy_only True
bash — upgrade platform
python upgrade_applications.py --deployment_name platform --redeploy_only True
⚠ If you get a "Kubernetes cluster unreachable" error, the kubectl context was reset. Run this and retry: kubectl config use-context default
ℹ If helm times out with "context deadline exceeded", the pod may have come up anyway. Check with: kubectl get pods -n impala-api If the pod shows Ready: 1/1, the upgrade succeeded — continue to the next command.
8
Verify Running Pods

Confirm all pods are running with the correct images.

bash — pod status
kubectl get pods -n ivix-ui kubectl get pods -n impala-api kubectl get pods -n impala-ui
bash — verify image tags
kubectl get pods -n ivix-ui -o jsonpath='{.items[*].spec.containers[*].image}' && echo kubectl get pods -n impala-api -o jsonpath='{.items[*].spec.containers[*].image}' && echo kubectl get pods -n impala-ui -o jsonpath='{.items[*].spec.containers[*].image}' && echo
✓ platform pod shows tag <PLATFORM_TAG>
✓ impala-api pods (×2) show tag <IMPALA_API_TAG>
✓ impala-ui pod shows tag <IMPALA_UI_TAG>
